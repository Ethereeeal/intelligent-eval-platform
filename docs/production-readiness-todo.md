## A. 已完成（2026-08 落地）

- **EIU 抽取改造实施方案固化（2026-08-26）**：新增 `docs/eiu-extraction-implementation-plan.md`，明确以证据、候选声明和评测意图为三层基座；按数据契约与人工审核、结构化 Block/Context Bundle、三色路由/黄色批审、重复关系/文档级对账、效率与校准五阶段实施，并给出每阶段验收标准。

- **知识点三色路由与黄色 LLM 审查（2026-08-26）**：规则不再因“抽到任意候选”而全部拦截 LLM；同条款多规则、引用/例外/列表、表格、长 Block、P0 与规则兜底分类会携带局部上下文和同 Block 候选进入一次 LLM 拆分、合并、补全与证据判断。LLM 离线或失败时黄色候选强制留在 `needs_review`，不被确定性检查误放行；补全“仅接受/不接受/不可”等制度谓词，降低有效限制条款的误报。

- **条款级黄色批量审查（2026-08-26）**：同一条款的黄色候选首次审查时按 `block_id` 连同规则候选一次送入 LLM；模型响应按 Block 分发，后续同条款 Block 复用结果，减少重复调用。未带 `block_id` 的既有模型响应保持按当前 Block 处理；条款批审不跨文档，证据仍受 Context Bundle 白名单约束。

- **二次上下文审查冲突转红（2026-08-26）**：模型请求补证并完成第二次审查后，平台比较两次含实质陈述的结论；若 statement 或动作不一致，保留可追溯证据但强制标记红色 `needs_review`，不进入自动生成或正式覆盖率。首次仅请求上下文不视为冲突。

- **知识点关系与文档级质量对账（2026-08-26）**：覆盖率接口新增只读关系诊断（精确重复、包含、重叠、冲突）和文档级风险（无知识点、仅排除、长段单候选、未解析引用）；概览仅显示可行动的风险摘要并跳转文档库，原始 pair 明细保留在接口中。该诊断不改变既有覆盖率分子/分母和冻结门禁。

- **语义重复改为证据合并建议（2026-08-26）**：抽取期的精确/语义重复不再直接标记排除；重复候选进入 `needs_review` 并携带 `merge` 操作建议，保留两个来源 Block，供人工合并后汇总证据。避免去重过程静默减少知识点、掩盖文档质量问题。

- **知识点人工状态回退（2026-08-26）**：已验证与已排除知识点在既有操作列可回退至 `needs_review`；回退会恢复可复核状态并清空排除原因，避免人工误判后只能依赖后端修库。

- **评估指标实际口径校准（2026-08-26）**：更新 `docs/project-evaluation-overview.md`，以当前源码、API 返回和前端展示为准，拆分文档/知识点/QA/Agent 四层指标；明确 Block 对账、知识点四项检查、QA 五项质检、冻结约束、首页概览和运行汇总的分子分母；将人工 Precision/Recall、多跳、泛化和中间过程错因定位标记为未实现能力，避免在汇报中与现状混用。
