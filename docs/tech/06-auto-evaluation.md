| 需求编号 | 需求 |
|---|---|

### 9.3 失败归因

| 需求编号 | 需求 |
|---|---|
| FR-DIAG-001 | D1-D8 归因：文档解析失败/知识表示失败/检索召回失败/排序上下文失败/评测样本缺陷/原始材料不足/安全策略失败/系统运行异常 |

## 2. 技术方案概览

### 2.1 待测系统适配器

```python
class TargetSystemAdapter:
    """标准适配器接口。"""

    def run_evaluation(self, case: EvalCase) -> CaseResult:
        """
        1. 将 case.question 发送给待测系统
        2. 记录待测系统返回的检索文段列表
        3. 记录待测系统返回的最终答案
        4. 对比 gold_answer（标准答案）vs system_answer（系统答案）
        5. 对比 gold_evidence（标准证据）vs system_retrieved（系统检索）
        6. 计算检索指标和运行指标
        """
```

### 2.2 检索指标计算

```
Evidence Recall@K:
  前K个检索结果中，命中了多少条金标准证据块

MRR (Mean Reciprocal Rank):
  第一条正确证据出现排名的倒数

Multi-hop Complete Recall@K:
  多跳题目所需全部证据是否均被召回
  同时报告"至少命中一跳"和"全部跳命中"
```

### 2.3 失败归因引擎

```
归因顺序（FR-DIAG-002）：
  1. 原始资料中是否真的有答案 → 否 → D6 原始材料不足
  2. Gold 问题/答案/证据是否正确 → 否 → D5 评测样本缺陷
  3. 原文是否被正确解析 → 否 → D1 文档解析失败
  4. 必要证据是否被召回 → 否 → D3 检索召回失败
  5. 证据是否进入最终上下文 → 否 → D4 排序/上下文失败
  6. 输出是否满足格式和安全要求 → 否 → D7 安全策略失败
  7. 系统运行是否正常 → 否 → D8 系统运行异常
```

### 2.4 Error Book

```
ErrorBook 记录：
  - case_id + 归因类型
  - 失败分析详情
  - 优化动作 + 修复前后指标
  - 是否产生其他类型退化
  - 聚类标记（相同根因的失败聚合）

高频失败 → 自动聚类 → 优先处理影响面大的根因
```

## 3. Demo 不做

Demo 阶段不实现自动评测和失败诊断的**所有**内容。Demo 的终点是"导出评测集"——平台产出一个合格的评测数据集，至于用这个数据集去评测什么系统、如何归因优化，是后续版本的事。
