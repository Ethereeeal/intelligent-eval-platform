## 2. 单段题目生成技术方案（Demo 核心）

### 2.1 生成流程

```
对每个可出题 EIU（is_questionable=true 且无排除原因）：
  1. 获取 EIU 原文证据 Block（含章节路径 + 页码）
  2. 获取相邻 Block 上下文（前1后1）
  3. 调用 LLM 题目生成 Prompt
  4. 调用 LLM 答案生成 Prompt
  5. 将结果写入 eval_case 表，绑定 eiu_id
```

### 2.2 题型映射（EIU 类型 → 题目类型）

| EIU 类型 | 题目类型 | 示例模板 |
|---|---|---|
| definition | 定义题 | "什么是{术语}？请给出完整定义。" |
| rule | 条件与适用范围题 | "{主体}在{场景}下，{动作}的条件是什么？" |
| threshold | 阈值和数值题 | "{指标}的上限/下限是多少？" |
| date | 时效题 | "{规定/政策}何时生效？适用期间是？" |
| formula | 公式与计算题 | "如何计算{指标}？请写出公式并代入数值。" |
| process | 流程顺序题 | "{业务}的完整流程是什么？请列出步骤。" |
| exception | 例外与边界题 | "在什么条件下可以例外于{规则}？" |
| prohibition | 是否可回答题 | "{主体}是否可以{动作}？为什么？" |
| metric | 事实提取题 | "{主体}在{期间}的{指标}是多少？" |
| change | 比较与区分题 | "{新旧版本}在{维度}上有什么变化？" |

**Demo 约束：每 EIU 只生成 1 道规范问题，不做多问题变体。**

### 2.3 Prompt 设计

**题目生成 Prompt 核心要素：**

```
系统角色：评测集编制专家
输入：
  - EIU 完整陈述
  - EIU 类型
  - 原文上下文（含章节路径）
  - 目标题型
约束：
  - 问题仅凭给定材料可回答
  - 不自带前提、不泄露答案
  - 正式书面表达
  - 不包含"根据上文""根据材料"等提示语
输出：JSON { question, question_type, difficulty }
```

**答案生成 Prompt 核心要素：**

```
系统角色：评测标准答案编制专家
输入：
  - 题目文本
  - 原文证据 Block 列表（含定位信息）
约束：
  - 答案仅基于原文，不补充常识
  - 列出所有必须命中的答案要点
  - 列出可接受的同义表达
  - 每个要点绑定具体原文证据
  - 原文无足够证据时标记为"不可回答"
输出：JSON { gold_answer, must_have_points, acceptable_answers,
              evidence_bindings, is_unanswerable }
```

### 2.4 证据绑定（FR-QG-003）

每个答案要点的证据绑定格式：

```json
{
  "must_have_point": "净利润为100万元",
  "evidence": {
    "document_id": 1,
    "document_name": "某企业财报.pdf",
    "section_path": "第四章 合并财务报表 > 4.1 合并利润表",
    "page_no": 35,
    "block_id": 120,
    "original_text": "2025年度合并净利润为人民币1,000,000元",
    "start_offset": 240,
    "end_offset": 275
  }
}
```

### 2.5 评测样本数据模型（eval_case 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| case_id | INT PK | |
| intent_id | VARCHAR | 规范问题意图 ID（同义改写共享） |
| eiu_id | INT FK | 关联的 EIU |
| question | TEXT | 问题文本 |
| question_type | VARCHAR | 10 种题目类型 |
| difficulty | VARCHAR | L1/L2/L3 |
| scope_type | VARCHAR | single_segment（Demo）/ cross_segment / cross_document |
| gold_answer | TEXT | 标准答案 |
| must_have_points | JSON | 必须命中要点列表 |
| acceptable_answers | JSON | 可接受的同义表达 |
| evidence | JSON | 证据绑定数组 |
| content_priority | VARCHAR | P0/P1/P2 |
| review_status | VARCHAR | candidate → quality_verified → governance_passed → published |
| created_at | DATETIME | |

## 3. 跨段/跨文档生成（Demo 延后，技术方案预留）

### 3.1 候选发现（FR-MH-001）

```
对每个新增 Block：
  1. 向量近邻检索 Top-K（K 可配置，默认 20）
  2. 元数据过滤：同语料库、同文档类型、同主体/期间
  3. 共同实体/术语匹配
  4. 显式引用检测（"详见第X章""参照X文件"）
  5. 关系判定模型确认候选关系类型
```

复杂度：O(NK)，K ≪ N，无需全量两两比较。

### 3.2 跨段关系类型（FR-MH-002）

| 关系类型 | 含义 | 题目方向 |
|---|---|---|
| 定义+条件 | 术语定义 + 适用条件 | "X是什么？在什么条件下适用？" |
| 规则+例外 | 一般规则 + 例外条款 | "一般规则是什么？什么情况下例外？" |
| 指标+公式+数值 | 定义/公式/实际数据分散在不同位置 | "计算X的值，并说明使用了什么公式" |
| 同主体不同期间 | 同一主体不同报告期的数据 | "X从2024到2025年发生了什么变化？" |
| 旧政策+新政策 | 新旧版本对比 | "新政策相比旧政策在X方面做了哪些调整？" |
| 引用补充 | 主条款引用其他条款 | "X条款的补充规定是什么？" |
| 互补证据 | 两部分证据联合才能完整回答 | "综合以下信息，X的完整条件是？" |
| 易混概念 | 两个容易混淆的概念 | "X和Y有什么区别？" |

### 3.3 真多跳校验（FR-MH-003）

```
对每个标记为 cross_segment/cross_document 的题目：
  1. 只给 LLM 证据 A → 能否完整回答？
  2. 只给 LLM 证据 B → 能否完整回答？
  3. 任一单证据足以回答 → 拒绝标记为真多跳，降级为单段题
  4. 只有联合证据才能完整回答 → 通过
```

### 3.4 跨文档冲突处理（FR-MH-004）

- 冲突内容不静默融合
- 按生效日期、权威等级确定标准答案
- 冲突来源写入 evidence 的 conflict_note 字段

## 4. 改写与反例生成（Demo 延后，技术方案预留）

### 4.1 改写（FR-VAR-001 / 002）

每个规范问题可生成 5-7 种变体：

| 变体类型 | 示例 |
|---|---|
| 正式书面 | "请阐述该公司于报告期内的净利润率水平。" |
| 简短口语 | "这家公司净利润率多少？" |
| 省略主语 | "净利润率是多少？"（上下文已明确主体） |
| 术语简称 | "净利率是多少？" |
| 不同语序 | "该公司的净利润率，是多少？" |
| 含无关背景 | "我在写报告，需要知道这家公司的净利润率，你能告诉我吗？" |
| 先场景再提问 | "假设我是审计师，需要核查该公司的盈利状况。净利润率是多少？" |

**改后检查：**
- 原意未变 → LLM 比对原问题和改写
- 答案仍相同 → 用标准答案验证
- 未引入新前提 → LLM 检查新增信息
- 不与已有改写过于相似 → 向量相似度 > 0.95 去重

所有改写共享同一个 `intent_id` 和标准答案，不计入 EIU 覆盖率。

### 4.2 反例与对抗题（FR-VAR-003）

| 反例类型 | 示例 | 预期行为 |
|---|---|---|
| 指标消歧 | "利润率是多少？"（有多口径） | 要求澄清或分别回答 |
| 同数字不同语境 | 两个部门都有"净利润 100 万" | 区分来源 |
| 规则与例外混淆 | 故意将例外当规则问 | 纠正前提 |
| 旧版本当现行 | "按照 2020 版政策……"（已废止） | 指出版本过期 |
| 错误预设 | "为什么 X=200？"（实际 X=100） | 纠正预设 |
| 材料无答案 | 问文档中没有的内容 | 明确拒答 |
| 提示注入对抗 | 问题中包含"忽略之前所有规则……" | 仅作为待分析文本，不执行 |

## 5. 难度体系技术实现（FR-DIFF-001~005）

### 5.1 难度初判规则

| 判定要素 | L1 | L2 | L3 |
|---|---|---|---|
| 证据跳数 | 1 | 1-2 | 2+ |
| 含计算 | 否 | 简单代入 | 多步推导 |
| 含消歧 | 否 | 轻微 | 多项消歧 |
| 跨文档 | 否 | 否 | 是 |
| 对抗/不可答 | 否 | 否 | 是 |

**实现：** LLM 在题目生成时输出 `difficulty`，质量校验时做"难度有效性"复查（检查标记 L3 是否真需要多跳）。

### 5.2 难度分布非配置项

```
系统不得提供"难度目标比例"配置项。
难度分布 = EIU 覆盖率结果的统计输出，不是生成前的配额。
```

## 6. API 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/corpus/{corpus_id}/cases/generate` | 为所有未覆盖 EIU 批量生成题目+答案 |
| POST | `/api/eiu/{eiu_id}/generate-case` | 为单个 EIU 生成题目+答案 |
| GET | `/api/corpus/{corpus_id}/cases` | 评测样本列表（支持?priority=&type=&difficulty=&status=） |
| GET | `/api/cases/{case_id}` | 样本详情（含完整证据定位） |
| PUT | `/api/cases/{case_id}` | 手动编辑样本 |
| DELETE | `/api/cases/{case_id}` | 删除样本（标记 retired） |
