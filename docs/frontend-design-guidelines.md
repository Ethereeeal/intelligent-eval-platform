# 前端设计与体验准则

## 目标

平台界面应服务于“快速判断、准确定位、可追溯分析”的工作流。需求描述提供业务边界；页面的信息架构、视觉层级、交互状态与细节由实现者主动补全，并在有关键取舍时先与产品确认。

## 设计原则

- 复用现有平台语言：顶级导航、目录树、指标卡、表格、标签、按钮、间距和色彩保持一致。
- 先摘要、后明细：工作台和报告页先展示可行动的指标与状态，再展示可筛选、可展开的原始数据。
- 任务路径优先：将用户的连续任务排成明确步骤，避免将不同阶段的配置、结果和管理内容平铺堆叠。
- 渐进披露：低频或高级配置默认收起；长文本、复杂归因和大量字段通过行展开、抽屉或详情视图呈现。
- 状态完整：每个数据区都必须考虑加载、空数据、失败、运行中、成功和不可操作状态，并给出下一步操作。
- 可追溯：版本、来源、运行状态、评分和归因应能在需要时连接起来，避免用户在页面间猜测数据关系。

## 常用模式

### 导航与工作台

- 顶级导航只承载平台级领域；同一领域的配置、结果和历史记录使用左侧二级导航或页内工作台。
- 左侧导航应与目录树一致：清晰选中态、图标、紧凑间距，内容区域保持连续而非重复套卡。

### 指标与报告

- 指标使用概览页同风格的指标卡：图标、名称、主数值和必要趋势/解释；不要只用换行文字罗列数字。
- 原始报告是测试分析的主体。筛选、搜索、排序是辅助操作，不能取代报告本身。
- 表格默认展示高频字段；完整问题、回答、证据和 ErrorBook 通过行展开或详情展示。
- 对结果优先提供状态、低分、异常、归因、维度、难度和耗时等筛选入口。

### 表单与配置

- 表单按用户的实际决策顺序分组，字段名称解释清楚；必填、敏感字段和默认值要可辨识。
- 接口密钥等敏感值默认掩码，不能进入展示记录或日志。
- 在提交不可逆或耗时任务前，明确展示输入范围、版本和预期影响。

## 实施与确认

若页面涉及新的信息架构、关键交互或视觉取舍，实现前需向用户说明：页面结构、主任务流、关键组件、默认状态和未确定项。交付前需进行视觉一致性、状态完整性、可访问性与响应式复核。
