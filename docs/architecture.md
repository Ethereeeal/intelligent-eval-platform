# Architecture

本文件描述系统的模块划分、数据流和运行方式。

## 平台定位

本平台是一个**问答生成平台**：从文档中自动抽取知识点（EIU），并生成可评测的问答对（或导出知识点本身）。

核心链路：

```
上传文档 → 解析Block → 抽取EIU（知识点） → 覆盖规划 → 生成问答对/导出知识点 → 质量门禁 → 导出
```

## 系统架构（四层）

1. **接入层**：前端管理台页面、HTTP API（FastAPI）
2. **业务层**：文档解析、EIU 抽取、题目生成、质量校验、版本管理、导出
3. **数据层**：SQLite（Demo）、本地文件系统、FAISS
4. **模型层**：BGE embedding（语义分段 + 向量化）、LLM（EIU 抽取 + 题目/答案生成 + 质量校验）

## 核心模块（7 个）

| 模块 | 职责 | Demo 状态 |
|---|---|---|
| 01-数据基础 | 语料库管理、文档上传/解析（版面感知 + BGE 语义分段）、Block 存储、向量化（FAISS 辅助）、文档更新 job 进度 | 必做 |
| 02-EIU 抽取与覆盖规划 | LLM 单通道 EIU 抽取（10 种类型 + 8 条拆分规则）、覆盖清单、加权覆盖率计算、实质 Block 对账 | 必做 |
| 03-评测集生成 | 单段题目+答案+证据绑定生成、两种输出模式（知识点 / 问答对）、泛化扩写 | 必做 |
| 04-质量门禁与治理审核 | 5 项基础质量校验（可回答性/忠实性/唯一性/证据充分性/问题相关性）、审核状态机 | 必做 |
| 05-数据集生命周期 | 版本冻结/导出（JSONL/JSON/Excel）、目录树浏览、表格视图+可视化、手动编辑、无问题提示 | 必做 |
| 06-评测后数据回流 | 接收外部评测反馈、回流工作台、修题闭环（不涉及自动评测） | Demo 不做 |
| 07-智能问答交互 | 对话式平台操作入口（上传/预览/编辑/问答）、意图解析、多轮对话 | Demo 不做 |

## 数据流

1. 文档上传 → 本地 `storage/raw/` + SQLite 元数据
2. 文档解析 → 版面感知（PyMuPDF/python-docx）+ BGE 语义分段 → Block + 原文定位
3. Block → BGE Embedding → FAISS 索引（辅助用途：去重提醒、跨段候选发现）
4. EIU 抽取 → LLM 逐 Block 抽取可评测信息单元 → `eiu` 表
5. 覆盖规划 → 确定性代码计算加权覆盖率 → `coverage_report`
6. 题目生成 → LLM 基于 EIU 生成题目+答案+证据绑定 → `eval_case` 表
7. 质量校验 → LLM 5 项检查 → `quality_check_result` 表
8. 导出 → JSONL / JSON / Excel → 评测集交付物

## 两种输出模式

| 模式 | 输入 | 产出 | Demo |
|---|---|---|---|
| A — 文档知识点 | EIU 表 | EIU 自然语言陈述 + 章节/证据定位，不含题目与答案 | 必做 |
| B — 问答对 | EIU + LLM 生成（或用户上传种子问答对） | 规范问答对 + 泛化扩写，含题目/答案/证据绑定 | 必做 |

## 存储体系（Demo 简化）

| 存储层 | Demo 实现 | 生产迁移 |
|---|---|---|
| 原始文件 | 本地 `storage/raw/` | MinIO |
| 关系型数据 | SQLite `storage/qa_gen.db` | PostgreSQL |
| 向量索引 | FAISS 本地文件 `storage/faiss.index` | 向量数据库 |
| 语义理解 | SQLite（EIU 表及其他语义表） | PostgreSQL |
| 配置与版本 | 环境变量 + 代码内 Prompt 模板 | 配置中心 |
