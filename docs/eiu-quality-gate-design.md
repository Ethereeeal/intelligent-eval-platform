# EIU 自动质量门禁、文档质量反馈与按用途选题方案

> 状态：已确认，待实现
>
> 日期：2026-09-06
>
> 需求依据：`evaluation_dataset_platform_brd.md` §8.24；如与旧 EIU 审核、P0 规则包或前端展示口径冲突，以本文件和 BRD V1.4 为准。

## 1. 目标与边界

知识点（EIU）是将文档转换为评测集的自动中间层。系统的目标不是让用户逐条审核大量知识点，而是在后端自动保证只有证据充分、语义边界清晰的知识点进入出题；文档问题则以可定位的反馈说明，而非单一质量总分或人工待办。

不在本方案中做跨文档补证。跨文档多跳题是后续独立能力，不能借用其他文档来补写当前文档的规则。

## 2. 术语与职责

| 概念 | 含义 | 是否面向用户展示 |
|---|---|---|
| `eiu_type` | 定义、规则、禁止、阈值、例外、流程等结构类型 | 可按需要展示 |
| P0/P1/P2 | 相对文档目的的重要性；决定自动处理强度与覆盖策略 | 否 |
| 绿色 | 已通过忠实性与完整性两项硬门禁，可进入 QA 生成；原子性仅为出题提示 | 是，作为正常知识点 |
| 黄色 | 仅 P0 在自动处理后仍未达到最低要求 | 是，沿用“待复核” |
| 红色 | 自动归档、排除出题的记录 | 是，沿用“已排除” |
| 文档质量反馈 | 原文对自动构建评测集造成的风险与系统处理 | 是，不要求确认 |

规则抽取回答“这是什么”；重要性判断回答“不覆盖会不会误解本文件”；QA 质检回答“这道题能否作为正式评测样本”。三者不得互相替代。

## 3. 自动处理流程

```text
文档解析为 Block
  → 规则抽取候选（类型、结构信号、原文证据）
  → 同文档上下文补证与 LLM 语义审查
  → 拆分/归并为规范知识点簇
  → 文档级批量重要性评估（P0/P1/P2）
  → 忠实性、上下文完整性两项硬门禁；原子性出题提示
  → 绿色进入 QA；黄色进入“待复核”；红色进入“已排除”
  → QA 生成、证据绑定与 QA 质检
  → 按用途选择题目并冻结版本
```

### 3.1 同文档补证

允许使用章节路径、父条款、同条款 Block、相邻 Block、显式引用条款、定义和表格表头。每份补证保存 `document_id`、`block_id`、`section_path`、证据角色和策略版本。无法补足或发现冲突时，保留原文并产出文档质量反馈，不由模型臆造结论。

### 3.2 原子性与归并

一条规范知识点只表达一个独立业务判断。相同业务场景、相同结论、相同范围和条件的重复表达可以归并；不同条件、例外、阈值、主体、时效或业务结果必须保留为不同的可考察点。归并只合并出题意图，保留全部候选和证据以供审计。

### 3.3 重要性与自动处置

重要性由模型在完整文档结构下批量判断，不由固定领域字典、规则类型或单个强制词决定：

| 等级 | 定义 | 未通过自动门禁后的处理 |
|---|---|---|
| P0 | 缺失会明显误解核心规则、关键边界、风险或关键流程 | 自动补证、扩大同文档上下文、二次审查；仍不足则黄色 |
| P1 | 有助于正确理解，但不改变核心结论 | 一次补证/重审；仍不足则红色归档 |
| P2 | 背景、示例、重复或低价值延伸 | 首次审查不足即红色归档 |

所有通过忠实性与上下文完整性两项硬门禁的 P0/P1/P2 都是绿色，都可进入 QA 生成；原子性警告随 EIU 传给 QA，默认增加多个单事实出题角度。

## 4. 质量门禁与文档反馈

知识点硬门禁只有两项，另保留一项非阻断提示：

1. 忠实性与可追溯性：陈述、条件、例外均由原文证据支持并能精确定位；
2. 上下文完整性：定义、指代、引用、前置条件、例外和表格结构已经补足；
3. 原子性提示：标记可能包含多个独立事实，供 QA 生成按角度拆题；不单独阻断 EIU。

知识点阶段不再使用“可测试性”正则。问题能否清楚表达、答案是否完整由 QA 生成与 QA 质检负责。

文档质量反馈与抽取同步生成，只展示可行动事实：定义缺失、引用无法解析、关键规则缺上下文、表格缺表头或单位、规则冲突、P0 未解决。展示“正常 / 有质量提示 / 有关键质量风险”及问题数量、影响范围、Block 定位、系统处理；不显示文档总分，不要求人工确认。

## 5. QA 的边界与人工指定纳入

绿色知识点是“允许进入生成”的质量结论，而非对某次模型调用的承诺。QA 生成超时、格式错误、重复、答案超证据或模板不合规，先作为生成层故障自动重试或记录；它不会自动降级知识点，也不会自动归因为文档问题。

用户可以对黄色或未被当前用途选中的绿色知识点执行人工指定纳入，保存原因后重跑两项硬门禁。人工指定不改变自动状态或重要性；红色“已排除”记录保持只读、不可操作。有证据的题可进入正式集，无证据试验题不得进入正式集或覆盖率分母。

## 6. 按用途构建评测集

| 用途 | 目标 | 选题策略 |
|---|---|---|
| 开发自测 | 快速发现明显功能、检索和理解错误 | 覆盖核心规则簇，选择代表性 P0 与关键例外；默认 10–20 题上限 |
| 测试全量测 | 验证覆盖与边界 | 全部绿色 P0/P1/P2，含关键例外、组合条件和边界题 |
| 业务测 | 验证真实业务价值 | 选择业务价值高的 P0/P1，排除纯技术、背景和低价值延伸 |

QA 记录增加“评测集适用性”字段，标记开发自测、测试全量测、业务测。它与 P0/P1/P2 独立，由系统基于目标自动判断，不要求用户维护主题字典。

## 7. 实施与迁移

1. 将当前规则分类中的优先级映射拆为 `eiu_type` 与 `importance_signals`；
2. 增加规范知识点簇、重要性理由、证据角色、自动处置原因、人工指定和质量策略版本；
3. 用忠实性与完整性两项硬门禁替换四项检查中的“可测试性”，将原子性作为 QA 出题提示，并改造黄/红自动处置；
4. 将现有重复/冲突诊断升级为自动归并与文档质量反馈；
5. 新增评测集用途配置与选题服务；
6. 文档更新和质量策略更新均触发 EIU、关联 QA 与覆盖报告重算；冻结版本保持不变；
7. 前端沿用“待复核”“已排除”及现有页面结构，不展示 P0/P1/P2。

验收应覆盖：同文档补证可定位、重复但独立可考察项不被误并、P0 未解决进入黄色、P1/P2 未解决进入只读归档、文档反馈不要求确认、不同用途生成不同选题集、人工指定不绕过证据门禁、策略重算不改写冻结版本。
