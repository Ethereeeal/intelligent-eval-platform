# EIU 抽取改造实施方案

> 状态：已确认，实施以本文为准。来源：[EIU抽取改造.txt](EIU抽取改造.txt)。
>
> 目标：把 EIU 明确为“候选业务声明”，以原文证据、经审核声明和评测意图构成评测集基座；避免规则切句直接决定覆盖率和评测集质量。
>
> **当前总体状态（2026-08-26）：P0 进行中，尚未完成。** 阶段 B、C 已完成；阶段 A 目前只完成部分数据契约、接口和前端操作入口，人工审核闭环仍缺少操作人审计信息、结构化字段编辑面板以及端到端数据库回归，因此不能将本次 EIU 改造表述为 P0 全部完成。

## 1. 目标架构与不变量

```text
Document Context Map
  ↓
结构化 Evidence Block ──→ Context Bundle
  ↓                         ↓
规则高召回候选 ─────────→ 三色路由
                              ├─ 绿色：确定性验证
                              ├─ 黄色：条款级 LLM 批量审查
                              └─ 红色：人工复核
  ↓
Verified Claim → 评测意图 → QA / 评分合同
```

必须满足：

1. Block 仅用于原文定位和上下文组织，不是知识点边界；一条知识点可绑定多个 Block。
2. 只有 `verified` 且可出题的知识点进入正式覆盖率分母和自动出题。
3. 每个候选必须可追溯到原文证据、路由原因和审查动作。
4. LLM 只审查黄色候选的 Context Bundle，不逐条重读全文；其输出必须经过原文回读校验。
5. 人工复核可以实际改变状态和内容，不能只是展示待办；所有人工操作可审计、可回溯。

## 2. 数据契约

### 2.1 Block 与上下文

保留现有 `document_block`，扩展其 `metadata_json`：

- `article_no`、`clause_no`、`item_no`、`list_path`；
- `lead_block_id`：列表/条件引导语；
- `table_id`、`header_block_ids`、`merged_cell_context`；
- `inherited_context`：主体、定义域、表头等继承语义；
- `reference_targets`：显式条款/附件/外部制度引用。

`ContextBundle` 为运行时对象，不要求先建独立表；它由当前条款、父级引导语、列表项、引用目标、表头和必要邻接 Block 组成，并保留每个来源 Block 的角色。

### 2.2 Claim / EIU

保持 `eiu` 表与接口名称兼容，逐步补齐结构化字段：

- `subject`、`predicate`、`object`、`modality`；
- `qualifiers_json`：条件、范围、期间、单位、例外；
- `route_color`：`green / yellow / red`；
- `route_reasons`：触发路由的可读原因；
- `review_action`：`pass / split / merge / complete_context / reject / human_review`；
- `review_attempts`、`review_model`、`review_prompt_version`；
- `source_candidate_ids`：拆分/合并的来源候选；
- `evidence_details` 统一支持 `direct / subject / qualifier / definition / reference / exception / conflict` 与 `source_span`。

### 2.3 人工审核操作

新增可审计的审核动作：

| 操作 | 效果 |
|---|---|
| 通过 | 将已核对候选设为 `verified` |
| 编辑并通过 | 更新声明/结构字段/证据后设为 `verified` |
| 退回待审 | 保留候选，记录原因和下一步 |
| 排除 | 设为 `rejected`，强制填写原因 |
| 合并 | 多个候选产生一个正式知识点，保留来源关系与全部证据 |
| 拆分 | 一个候选产生多个正式知识点，保留来源关系与全部证据 |

人工操作写入现有审计日志，并在知识点上保留最后审核者、时间和操作原因。

## 3. 三色路由

### 3.1 绿色：确定性通过

同时满足以下条件：显式主体；单一业务义务/谓词；无未解析指代和跨条引用；无列表引导依赖；无多个并列动作；原文中出现的数值、单位、条件完整；证据可直接回读。

绿色候选由确定性四项检查验证。任一条件不满足即不得直接标为 `verified`。

### 3.2 黄色：条款级 LLM 审查

任一条件触发黄色：多个规则谓词、引用/指代、规则与例外混合、列表、长 Block、表格、继承主体/指标、类型或优先级不确定、候选间包含/重叠关系、P0 条款。

LLM 输入为同一条款的候选和 Context Bundle，输出动作必须为 `pass / split / merge / complete_context / reject / human_review` 之一。LLM 可以建议类型、优先级和结构字段，但平台必须做证据回读、枚举校验和字段完整性校验后才能落库。

### 3.3 红色：人工复核

以下情况进入红色：P0 证据不完整、制度冲突、外部引用缺失、OCR/表格结构异常、两次 LLM 审查不一致、无法消除指代、LLM/规则结果无法通过原文回读。

红色项不进入正式覆盖率分母，也不自动生成问答。

## 4. 分阶段实施与验收

### 阶段 A：数据契约与人工审核闭环（P0）

> 实施状态（2026-08-26）：进行中，尚未完成。已完成结构化 Claim 字段、路由/审查字段、通过/编辑/排除、合并/拆分、已通过/已排除项退回待审的 API 与前端入口；仍待补操作人身份、审核时间/原因等完整审计信息、结构化字段编辑面板、证据明细查看，以及端到端数据库回归。

1. 迁移 EIU 审查、路由和结构化字段；接口返回完整字段。
2. 新增审核 API：详情、通过、编辑通过、退回、排除、合并、拆分。
3. 前端在“待复核”项提供证据查看、编辑和上述操作；不可仅显示数字。

验收：任意待复核知识点可在前端完成一次通过、一次结构化编辑通过和一次排除；操作后状态、覆盖分母、出题可用性、证据链与审计记录一致，并通过真实数据库回归验证。

### 阶段 B：结构化 Block 与 Context Bundle（P0）

> 实施状态（2026-08-26）：已完成。DOCX 保留正文/表格顺序、条款/列表结构与表头；Context Map 支持父项、引导语、同条款、显式引用、定义和表头，并可一次受控扩展补证。

1. DOCX/PDF 优先按条、款、项、列表项切分；不再把超长条文视作普通段落。
2. 保存引导语、父子层级、表头与引用目标。
3. 实现条款级 Context Bundle 组装和证据角色。

验收：列表引导语+列表项、显式“第X条”引用、表头+数据行均可组成完整上下文；原文定位不丢失。

### 阶段 C：正式三色路由与黄色批审（P0）

> 实施状态（2026-08-26）：已完成。动作协议、候选来源和多角色证据、严格绿色门槛、按 `block_id` 分发并复用的同条款黄色批量审查，以及“上下文补充后二次审查结论不一致即转红”的规则均已落地。

1. 以同一个候选级复杂度/风险评估器计算 `route_color` 和原因。
2. 绿色严格验证；黄色按条款批量 LLM 审查；红色进入人工队列。
3. LLM 输出动作、来源候选映射、证据绑定和失败回退完整落库。

验收：样例中的“仅接受我行开具”与“不接受他行开立”被 LLM 合并并保留双证据；公式、阈值、外部引用分别得到正确类型和状态。

### 阶段 D：重复关系与文档级对账（P1）

> 实施状态（2026-08-26）：已完成。已完成 exact duplicate / contains / overlaps / conflicts 关系诊断、文档级遗漏检查、覆盖率/概览风险摘要和文档表内关系提示；语义重复不再静默排除，而是转为待复核的合并建议，可用现有人工合并操作保留并汇总证据。关系提示不自动合并，仍要求人工确认。

1. 重复检测区分 exact duplicate、contains、overlaps、conflicts；重复优先合并证据而非简单排除。
2. 实现文档级遗漏检查：无声明条款、P0 关键词、例外/一般规则、未解析引用、长条文单一候选、附件误抽。
3. 覆盖报告增加候选/路由/引用/关系质量指标。

验收：覆盖率可追溯到 Verified Claim；报告能列出未解析引用、红色项和无声明条款。

### 阶段 E：效率、校准与生产化（P2）

> Demo 决策（2026-08-26）：不纳入当前演示闭环，仅作为生产化前待办。现有抽取与质检闭环不依赖本阶段能力；汇报中不得把缓存命中率、人工 Precision/Recall 或生产级并发治理表述为已实现。

1. 审查结果缓存、受影响条款增量重审、有界并发和成本监控。
2. 小模型初审/大模型争议复审、两次审查一致性策略。
3. 双人标注与仲裁校准集，报告 Precision/Recall、跨块引用召回率和人工一致性。

## 5. 实施纪律

- 每一阶段先补测试，再实现，再用样例文档回归；不得只以候选数量或自动通过率判断质量。
- 未实现阶段不得在前端或汇报中表述为已具备。
- 当前工作区中的“单 Block 黄色 LLM 原型”仅作为阶段 C 的参考，不作为最终设计；实施阶段 A/B 后按本文替换。
