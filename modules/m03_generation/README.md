## 2. 单段题目生成技术方案（Demo 核心）

### 2.1 生成流程

> 题目与答案在一次 LLM 生成调用中基于同一 EIU 上下文**同时产出**（见 2.3：题目/答案两个 Prompt 实为同一次调用的两段关注点拆分，并非两次独立异步调用）。由于问题扎根于该 EIU 的原文证据，路径 1 生成的问题默认可答；`is_unanswerable` 仅在 EIU 自身信息不足等兜底场景下出现（详见 2.3 答案 Prompt）。

```
对每个可出题 EIU（is_questionable=true 且无排除原因）：
  1. 获取 EIU 原文证据 Block（含章节路径 + 页码）
  2. 获取相邻 Block 上下文（前1后1）
  3. 一次 LLM 生成调用：同时产出 题目 + 标准答案 + 证据绑定（题目侧与答案侧约束见 2.3，二者同上下文、同调用）
  4. 将结果写入 eval_case 表，绑定 eiu_id
```

### 2.2 题型映射（EIU 类型 → 题目类型）

| EIU 类型 | 题目类型 | 示例模板 |
|---|---|---|
| definition | 定义题 | "什么是{术语}？请给出完整定义。" |
| rule | 条件与适用范围题 | "{主体}在{场景}下，{动作}的条件是什么？" |
| threshold | 阈值和数值题 | "{指标}的上限/下限是多少？" |
| date | 时效题 | "{规定/政策}何时生效？适用期间是？" |
| formula | 公式与计算题 | "如何计算{指标}？请写出公式并代入数值。" |
| process | 流程顺序题 | "{业务}的完整流程是什么？请列出步骤。" |
| exception | 例外与边界题 | "在什么条件下可以例外于{规则}？" |
| prohibition | 是否可回答题 | "{主体}是否可以{动作}？为什么？" |
| metric | 事实提取题 | "{主体}在{期间}的{指标}是多少？" |
| change | 比较与区分题 | "{新旧版本}在{维度}上有什么变化？" |

**Demo 约束：每个可出题 EIU 至少生成 1 道规范问题；支持从不同角度（取值查询/条件判断/流程步骤/定义解释/例外边界/对比区分等）对同一 EIU 提问，生成多道相关题作为增强，多角度题共享同一 eiu_id、不重复计 EIU 覆盖率。**

### 2.3 Prompt 设计

> 题目与答案提示词分列，仅为**约束聚焦**（题目侧关注"不泄露答案、表述规范"，答案侧关注"仅基于原文、必中要点、绑定证据"），实际在一次 LLM 调用中合并输出 `{ question, question_type, difficulty, gold_answer, must_have_points, acceptable_answers, evidence_bindings, is_unanswerable }`。拆分描述也便于在「用户上传问答对（路径 2）」「泛化改写」等场景单独复用答案/证据绑定约束。

**题目生成 Prompt 核心要素：**

```
系统角色：评测集编制专家
输入：
  - EIU 完整陈述
  - EIU 类型
  - 原文上下文（含章节路径）
  - 目标题型
约束：
  - 问题仅凭给定材料可回答
  - 不自带前提、不泄露答案
  - 正式书面表达
  - 不包含"根据上文""根据材料"等提示语
输出：JSON { question, question_type, difficulty }
```

**答案生成 Prompt 核心要素：**

```
系统角色：评测标准答案编制专家
输入：
  - 题目文本
  - 原文证据 Block 列表（含定位信息）
约束：
  - 答案仅基于原文，不补充常识
  - 列出所有必须命中的答案要点
  - 列出可接受的同义表达
  - 每个要点绑定具体原文证据
  - 原文无足够证据时标记为"不可回答"（is_unanswerable=true）。该标记用于三类场景，而非怀疑路径 1 的题面：① EIU 陈述本身模糊/信息不全，单独无法支撑规范题；② 用户上传问答对（路径 2）或泛化题的种子答案/证据缺失；③ 作为质量门禁（见 04）的输入，明确"此题无解"而不伪造答案。路径 1 单 EIU 生成因问题扎根原文，通常不为 true。
输出：JSON { gold_answer, must_have_points, acceptable_answers,
              evidence_bindings, is_unanswerable }
```

### 2.4 证据绑定（FR-QG-003）

每个答案要点的证据绑定格式：

```json
{
  "must_have_point": "净利润为100万元",
  "evidence": {
    "document_id": 1,
    "document_name": "某企业财报.pdf",
    "section_path": "第四章 合并财务报表 > 4.1 合并利润表",
    "page_no": 35,
    "block_id": 120,
    "original_text": "2025年度合并净利润为人民币1,000,000元",
    "start_offset": 240,
    "end_offset": 275
  }
}
```

### 2.6 输出模式（Demo 核心）

平台在最终输出时支持两种模式，由用户在生成/导出时选择：

**模式 A — 文档知识点（EIU 自然语言版本）**
- 直接输出 EIU 的自然语言陈述，不生成题目与标准答案。
- 每条知识点含：完整陈述、类型、优先级、章节路径、原文证据定位。
- 适用：知识梳理、资料对齐、人工出题前置；导出物即"文档知识点清单"。
- 数据来源：`eiu` 表（`statement` + `evidence_blocks`），无需 `eval_case`。

**模式 B — 问答对（规范题 + 泛化，泛化支持用户上传问答对）**

模式 B 以"问答对"为产出单位，支持两条输入路径，最终都可选进入泛化：

- **路径 1 — 从文档生成**：为每个可出题 EIU 至少生成一道规范问答对（题目+答案+证据，见 2.1–2.5），可从不同角度生成多道相关题作为增强（见 2.2 Demo 约束），统一写入 `eval_case` 表（均绑定同一 `eiu_id`）。独立即可导出"问答对集"，不要求用户上传问题。
- **路径 2 — 用户上传问答对**：用户直接上传自己的问答对（question + answer，可带证据），经质量校验后作为种子进入泛化流程；适用于已有题面、希望批量扩写的场景，无需先经 EIU 抽取。

**泛化（两条路径共用，可选项）**：以种子问答对（用户上传的，或路径 1 系统生成的规范问答对）为输入，扩写/改写/关联出数量更多、表述更多样的**相关问题对**：
  - 改写扩写：同义改写、口语化、省略主语、语序变换、加入场景等（见 4.1）；
  - 关联扩展：生成追问/对比/边界等相关问题；
  - 所有泛化结果共享同一 `intent_id` 与标准答案（用户上传路径复用其原答案），不重复计入覆盖率。
- 即：模式 B 默认输出"每 EIU 至少一道规范问答对（可多角度生成多道相关题）"或"用户上传的问答对"；开启泛化后，额外输出"数量更多的相关问题对"集合。

## 3. 跨段生成（Demo 延后，技术方案预留）

### 3.1 候选发现（FR-MH-001）

```
对每个新增 Block：
  1. 向量近邻检索 Top-K（K 可配置，默认 20）
  2. 元数据过滤：同语料库、同文档类型、同主体/期间
  3. 共同实体/术语匹配
  4. 显式引用检测（"详见第X章""参照X文件"）
  5. 关系判定模型确认候选关系类型
```

复杂度：O(NK)，K ≪ N，无需全量两两比较。

### 3.2 跨段关系类型（FR-MH-002）

| 关系类型 | 含义 | 题目方向 |
|---|---|---|
| 定义+条件 | 术语定义 + 适用条件 | "X是什么？在什么条件下适用？" |
| 规则+例外 | 一般规则 + 例外条款 | "一般规则是什么？什么情况下例外？" |
| 指标+公式+数值 | 定义/公式/实际数据分散在不同位置 | "计算X的值，并说明使用了什么公式" |
| 同主体不同期间 | 同一主体不同报告期的数据 | "X从2024到2025年发生了什么变化？" |
| 旧政策+新政策 | 新旧版本对比 | "新政策相比旧政策在X方面做了哪些调整？" |
| 引用补充 | 主条款引用其他条款 | "X条款的补充规定是什么？" |
| 互补证据 | 两部分证据联合才能完整回答 | "综合以下信息，X的完整条件是？" |
| 易混概念 | 两个容易混淆的概念 | "X和Y有什么区别？" |

### 3.3 真多跳校验（FR-MH-003）

```
对每个标记为 cross_segment 的题目：
  1. 只给 LLM 证据 A → 能否完整回答？
  2. 只给 LLM 证据 B → 能否完整回答？
  3. 任一单证据足以回答 → 拒绝标记为真多跳，降级为单段题
  4. 只有联合证据才能完整回答 → 通过
```

### 3.4 跨文档生成（Demo 不做，方案预留）

**Demo 阶段不做跨文档生成**，以下为后续版本方案：当用户的生成范围包含**多个文档**且显式开启"跨文档"时，平台可生成跨文档综合问题。

**生成方法：组合 EIU（推荐），而非组合已生成的问答对。**

- **组合 EIU（采用）**：先抽取各文档 EIU，再选取跨文档相关的 EIU（通过共同实体/术语/引用/同主体不同期间等）组合，由 LLM 基于组合后的 EIU 陈述统一生成问题 + 标准答案 + 跨文档证据绑定。
  - 优点：答案连贯、证据可追溯到多个文档的 EIU、可在生成时控制**不重复计覆盖**（每个 EIU 仅计一次覆盖）。
  - 候选发现复用跨段的关系类型与近邻检索（FR-MH-001/002），检索范围跨文档；真多跳校验复用 FR-MH-003（任一单文档证据可完整回答则降级为单文档题）。
  - 每道跨文档题在 `eval_case` 绑定多个 `eiu_id`，覆盖率按 EIU 去重统计。

- **为什么不组合"已生成的问答对"**：直接拼接两个独立问答对的问题/答案，难以形成连贯的综合问法，且受限于已有题目表述、泛化性差；该方式更适合做泛化/改写，而非跨文档综合题。

> Demo 阶段不生成跨文档题（仅单文档内生成）；后续版本可支持多选文档开启跨文档。跨文档题导出隔离规则见 05 §4.2。

## 4. 改写与泛化生成（Demo 延后，技术方案预留）

> 说明：改写扩写已作为「输出模式 B — 泛化」的必做能力在 2.6 描述；本节保留反例/对抗题的预留方案。

### 4.1 改写（FR-VAR-001 / 002）

每个规范问题可生成 5-7 种变体：

| 变体类型 | 示例 |
|---|---|
| 正式书面 | "请阐述该公司于报告期内的净利润率水平。" |
| 简短口语 | "这家公司净利润率多少？" |
| 省略主语 | "净利润率是多少？"（上下文已明确主体） |
| 术语简称 | "净利率是多少？" |
| 不同语序 | "该公司的净利润率，是多少？" |
| 含无关背景 | "我在写报告，需要知道这家公司的净利润率，你能告诉我吗？" |
| 先场景再提问 | "假设我是审计师，需要核查该公司的盈利状况。净利润率是多少？" |

**改后检查：**
- 原意未变 → LLM 比对原问题和改写
- 答案仍相同 → 用标准答案验证
- 未引入新前提 → LLM 检查新增信息
- 不与已有改写过于相似 → 向量相似度 > 0.95 去重

所有改写共享同一个 `intent_id` 和标准答案，不计入 EIU 覆盖率。

### 4.2 反例与对抗题（FR-VAR-003）

| 反例类型 | 示例 | 预期行为 |
|---|---|---|
| 指标消歧 | "利润率是多少？"（有多口径） | 要求澄清或分别回答 |
| 同数字不同语境 | 两个部门都有"净利润 100 万" | 区分来源 |
| 规则与例外混淆 | 故意将例外当规则问 | 纠正前提 |
| 旧版本当现行 | "按照 2020 版政策……"（已废止） | 指出版本过期 |
| 错误预设 | "为什么 X=200？"（实际 X=100） | 纠正预设 |
| 材料无答案 | 问文档中没有的内容 | 明确拒答 |
| 提示注入对抗 | 问题中包含"忽略之前所有规则……" | 仅作为待分析文本，不执行 |

## 5. 难度体系技术实现（FR-DIFF-001~005）

### 5.1 难度初判规则

| 判定要素 | L1 | L2 | L3 |
|---|---|---|---|
| 证据跳数 | 1 | 1-2 | 2+ |
| 含计算 | 否 | 简单代入 | 多步推导 |
| 含消歧 | 否 | 轻微 | 多项消歧 |
| 跨段 | 否 | 否 | 是 |
| 对抗/不可答 | 否 | 否 | 是 |

**实现：** LLM 在题目生成时输出 `difficulty`，质量校验时做"难度有效性"复查（检查标记 L3 是否真需要多跳）。

### 5.2 难度分布非配置项

```
系统不得提供"难度目标比例"配置项。
难度分布 = EIU 覆盖率结果的统计输出，不是生成前的配额。
```
